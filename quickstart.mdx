This guide takes you from a blank environment to a working JAZ agent. You will install the package, configure an API key, and progressively build up from a one-liner that returns an integer to an agent that calls a custom tool and spawns nested sub-agents.

<Note>
Every input to `invoke` — including the prompt — is a **keyword argument**. `invoke()`'s positional arguments are hooks (like `ReturnType(int)`) and an optional `ConfigOverride`. Writing `invoke("Calculate the factorial of 10")` is a `TypeError`, not a shorthand. Always use `invoke(task="...")` or any other keyword name that makes sense for your task.
</Note>

<Steps>

### Install JAZ

Install the `jaz-lang` package from PyPI. The distribution is named `jaz-lang`; the import name is `jaz`.

```bash
pip install jaz-lang
```

Verify the install:

```python
import jaz
print(jaz.__version__)
```

### Set your API key

JAZ reads provider credentials from the environment using each provider's standard variable name.

<Tabs>
  <Tab title="OpenAI">
    Export your key in your shell profile so it is always available, or set it for the current session:

    ```bash
    export OPENAI_API_KEY="sk-..."
    ```

    For a project-scoped key, add it to a `.env` file at the project root and load it with [direnv](https://direnv.net/):

    ```bash
    # .env
    OPENAI_API_KEY=sk-...
    ```

    ```bash
    # .envrc  (direnv picks this up on cd)
    dotenv
    ```

    The default model route for LiteLLM is `openai/gpt-4o`. You can change the model at any time with `jaz.configure`.
  </Tab>
  <Tab title="GitHub Copilot (no API key)">
    If you have a Copilot subscription, install the `copilot` extra and authenticate with the GitHub CLI — no provider API key required:

    ```bash
    pip install "jaz-lang[copilot]"
    gh auth login
    ```

    Then configure JAZ to use the Copilot backend:

    ```python
    import jaz
    from jaz.llm import CopilotLLM

    jaz.configure(llm=CopilotLLM(model="gpt-4o"))
    ```

    Authentication checks `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, and `GITHUB_TOKEN` in that order, then falls back to your `gh`/`copilot` CLI login.
  </Tab>
</Tabs>

### Run your first invoke

`invoke` runs an agent and returns its result. Pass a `ReturnType` hook to declare and enforce the return type:

```python
from jaz import invoke
from jaz.hooks import ReturnType

result = invoke(
    ReturnType(int),
    task="Calculate the factorial of 10",
)
print(result)  # 3628800
```

The agent writes Python code in its REPL, executes it, observes the result, and calls `return 3628800` when done. JAZ validates that the returned value is an `int` before handing it back to you.

### Pass custom data and get a list back

Any keyword argument you pass becomes a named variable in the agent's REPL. The agent can read it, iterate over it, and use it directly:

```python
from jaz import invoke
from jaz.hooks import ReturnType

result = invoke(
    ReturnType(list),
    task="Double each number in the list",
    numbers=[1, 2, 3, 4, 5],
)
print(result)  # [2, 4, 6, 8, 10]
```

The agent sees the `numbers` variable bound in its namespace. Its docstring and type annotation (if any) render in the prompt header so the model knows what it is working with.

### Add a custom tool

A tool is just a Python function passed as a keyword argument. Its signature and docstring are what the agent reads — no registration, no decorator required:

```python
from jaz import invoke
from jaz.hooks import ReturnType


def web_search(query: str) -> list[str]:
    """Search the web and return result snippets."""
    # Replace with a real implementation, e.g. using httpx + a search API
    ...


result = invoke(
    ReturnType(dict),
    task="Look up each name and summarize what you find",
    names=["ada", "grace"],
    web_search=web_search,
)
```

The agent sees `` `web_search(query: str) -> list[str]`: Search the web and return result snippets. `` in its prompt and calls `web_search(...)` directly from its REPL. Tools and data sit side by side in the same call — no separate tool registry.

<Tip>
To group related tools under one name, pass an object instead of a function. The agent calls its public methods as `utils.my_tool(...)`. To make a tool available to all nested `invoke` calls automatically, use `jaz.scope`:

```python
from jaz import scope, invoke
from jaz.hooks import ReturnType

with scope(web_search=web_search):
    result = invoke(ReturnType(dict), task="Research these topics", topics=["AI", "Python"])
    # nested invokes spawned by the agent also see `web_search`
```
</Tip>

### Use recursive sub-agents

An agent can call `jaz.invoke` inside its own REPL to delegate sub-tasks. Use `RecursionLimit` to cap the nesting depth:

```python
from jaz import invoke
from jaz.hooks import RecursionLimit, ReturnType

with RecursionLimit(max_depth=3):  # optional; recursion is unbounded by default
    result = invoke(
        ReturnType(list),
        task="""
        For each item, use jaz.invoke to process it independently.
        Combine and return the results.
        """,
        items=["apple", "banana", "cherry"],
    )
```

Each nested `invoke` inherits the hook context and budget from its parent. Budget hooks like `BudgetPool` automatically track cost and call counts across the entire recursion tree.
